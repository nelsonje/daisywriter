# daisywriter: plan

> Living design doc: refine it here as decisions change.

## 1. Goal
daisywriter is a Windows desktop app (it also runs on macOS for development) that does **mail merge onto a daisywheel typewriter**:
1. The user picks a **Word template** (.docx) and an **Excel data file** (.xlsx, first row = headers).
2. The app **validates** that the merge can be done and reports clear, actionable problems.
3. It produces a **list of merged letters** with a typewriter-accurate preview.
4. The user **prints all letters in sequence**, or **selects individual letters to print or reprint**.
5. Optionally, it adds **simulated typing errors with strikeover corrections**, only in the letter body. The body is auto-detected, or set with explicit `{{body}} … {{/body}}` markers.
6. Paragraphs are **re-wrapped** to the typewriter's margins and pitch. Word's own line breaks are ignored, and only paragraph breaks and explicit manual line breaks are kept.

The typewriter connects through a USB printer-class parallel adapter (the Prolific PL2305, 067b:2305, or Sabrent's, 1a86:7584), which the app drives **directly, not through Windows print queues**. That's the same approach as `../olympia-compact-electronic-2/cmpprint.py`.

## 2. Decisions made so far
| Topic | Decision |
|---|---|
| Shape | Core library + CLI first, then a GUI on the same library |
| Distribution | MSI installer (PyInstaller onedir + WiX v5), built in GitHub Actions on Windows |
| Device access | Windows: ctypes against inbox `usbprint.sys` (no driver install). macOS/Linux: pyusb/libusb. |
| Merge tags | **Both** real Word `MERGEFIELD`s and plain-text placeholders (`{{Name}}` and typed `«Name»`) |
| Error zone | **Auto-detected** from letter structure (salutation → closing). Optional explicit `{{body}} … {{/body}}` markers override it. |
| Correction style | **Strikeover**, selectable as x-out / overstrike-in-place / **mix (default)** |
| Machines | **Profile-driven** from day one, with several typewriters described in TOML |
| Word headers/footers | **Ignored** (letterhead assumed pre-printed); only the document body is typed |
| Paper feed | **Per profile**: `single_sheet` (prompt before each page) or `continuous` (FF, no pause) |
| Indents | **Kept**, converted to whole columns (left, first-line, hanging) |
| Paper size and margins | **From the template's page setup** in Word (Layout > Size, Margins), fitted inside the typewriter's keyboard margins (`frame.py`, §8) |
| Page numbers | **Optional, generated by daisywriter** (Word's page numbers won't match the re-wrapped pages). Off by default. |
| Value formats | **As displayed in Excel** (daisywriter renders the cell's number format itself, US conventions). A format in the template overrides it, so most users never need template formatting. Excel's General format falls back to daisywriter defaults. |
| First machines | **Nakajima family**: Swintec 1146 CMP (firmware 335-U), Swintec 1146 CM (firmware 3Z28) and Olympia Electronic Compact 2 (and likely the 1186 CMP). Other machines later (§15). |

## 3. Stack
- **Python 3.12**, **uv**, `src/` layout, pytest, ruff
- **python-docx** for paragraphs, runs, alignment, bold/underline, and headers/footers, plus our own walker over the raw XML for merge fields
- **openpyxl** (`read_only=True, data_only=True`) to read the Excel records
- **PySide6** for the GUI
- **pyusb** (non-Windows only) and **ctypes** (Windows) for the transports
- **PyInstaller** + **WiX Toolset v5** for the MSI, built and published by GitHub Actions

## 4. Pipeline / architecture
```
.docx ──► template.py ──► Template (paragraph model + fields + regions)
.xlsx ──► records.py  ──► list[Record] (header → display string)
                │
        validate.py  (template × records × profile → Issues)
                │
          merge.py  ──► MergedLetter (paragraphs with field values substituted)
                │
         errors.py  ──► (optional) inject typos + strikeover corrections in body spans, seeded
                │
         layout.py  ──► Pages → Lines → Cells (char, bold, underline, overstrike)
                │
        render.py   ──► bytes per page, via the Profile (charset map, bold/underline method, newlines)
                │
  transports/*  +  job.py  ──► typewriter (line chunking, timeouts, status, paper prompts)
```

```
src/daisywriter/
  model.py          # Span(text, bold, underline, field=None, region), Paragraph(align, spans, kind)
  template.py       # docx → Template; MERGEFIELD + placeholder parsing
  region.py         # paragraph roles: explicit {{body}} markers, else salutation→closing auto-detect
  records.py        # xlsx → records; header normalization; cell → string formatting
  issues.py         # Issue(level, message, where, letter)
  values.py         # Word-style date/number pictures, case switches
  profile.py        # profile loader, paper stocks, printwheel character mapping
  pipeline.py       # runs template → records → merge → layout; field/profile cross-checks (§6)
  samples.py        # prototype template + spreadsheet (`daisywriter make-samples`), used by tests
  merge.py          # Template + Record → MergedLetter
  errors.py         # typing-error injection (seeded RNG, QWERTY-neighbor model)
  layout.py         # re-wrap + alignment + pagination → Page/Line/Cell grid
  preview.py        # Page → plain/ANSI text or HTML preview
  render.py         # Page → bytes per Profile (phase 2)
  profiles/         # *.toml + loader (dataclass)
  transports/       # base.py, pyusb.py, usbprint.py (Windows), file.py (dry-run), emulator.py
  job.py            # send loop: chunk after LF/FF, per-line timeout, line pause, progress + pause-for-paper callbacks
  session.py        # a merge run: letters, print status per letter, seeds; saved as JSON next to the data file
  cli.py            # validate | preview | print [--letters 1,4-6] | status | init | test
  gui/              # PySide6 app (phase 3)
tests/fixtures/     # sample .docx/.xlsx, golden layouts and golden byte streams
```

## 5. Reading the Word template (`template.py`)
- Walk each `w:p` in the document body in document order. Section headers and footers are ignored, and a template that has them gets an info message. Build `Span`s from runs. Each span has text, **bold**, **underline**, **strikethrough** (double strikethrough is typed as single), and the effective formatting, where style inheritance is resolved through python-docx (`run.bold` is `None`, so fall back to the paragraph/character style).
- **Real merge fields:**
  - Handle `w:fldSimple` with `MERGEFIELD Name`, and complex fields (`w:fldChar begin` → `w:instrText` → `separate` → result runs → `end`).
  - A MERGEFIELD becomes `Span(field="Name")` and takes the formatting of its result run. Field switches (`\* Upper`, `\* Caps`, `\@ "MMMM d, yyyy"`, `\# "0.00"`) are parsed, and the common ones are supported.
  - Placeholders take the same format pictures after a colon: `{{InvoiceDate:MMMM d, yyyy}}`.
  - A Word `PAGE` field in the body is ignored with a warning; use daisywriter's page numbering instead (§8).
  - Other fields (`DATE`, `NEXT`, `IF`, `SKIPIF`) produce a validation issue. `DATE` may be supported as "today".
- **Plain placeholders:** after joining a paragraph's runs, a regex matches `{{ Name }}` and `«Name»` across run boundaries. Word often splits typed text across runs, so this has to work on the joined text, and formatting is kept per character.
- **Body region** (`region.py`): each paragraph gets a role, and only `body` paragraphs can receive typing errors. Detection runs once on the template, so every letter uses the same zone.
  - **Explicit markers win.** If the template contains `{{body}}` / `{{/body}}`, only text inside the markers is body. Markers can be standalone paragraphs (removed from the output) or inline. Validation checks that they're balanced and not nested.
  - **Otherwise, auto-detect** from standard letter structure:
    - **Salutation:** the first short paragraph matching `^(Dear|To whom it may concern|Hello|Hi|Greetings)\b…[,:]$`. Merge fields count as words, so `Dear {{FirstName}},` matches.
    - **Complimentary close:** the first short paragraph after the salutation matching a list such as `Sincerely`, `Yours truly`, `Very truly yours`, `Best regards`, `Kind regards`, `Respectfully`, `Cordially`, or `Thank you`, followed by a comma. The list is extensible in config.
    - **Body:** paragraphs strictly between the two. Inside that range, `Re:`/`Subject:` lines, centered headings, and paragraphs that are entirely bold or underlined are excluded.
    - **Never body:** the date, inside address, and anything from the closing onward (signature, typed name and title, initials, `Enc.`, `cc:`, `P.S.`).
  - **Fallback:** if no salutation or closing is found, no paragraph is body and validation warns: "Couldn't find the letter body; add {{body}} markers to enable typing errors." Errors are never applied to the whole letter by guesswork.
  - The detected zone is reported in validation ("body: paragraphs 6–11, auto-detected") and **shaded in the preview**, so the user can check it before printing.
- **Paragraph properties:** alignment (left/center/right/justify), "keep with next", and blank paragraphs (kept as blank lines). Space before/after and empty paragraphs are added up in points and rounded to whole blank lines once per gap (threshold configurable), so Word's default 8 pt space-after doesn't inflate runs of empty paragraphs. Word's line spacing (1.08, 1.15, ...) is ignored; the typewriter's lpi decides. Manual line breaks (`w:br`) become forced breaks, and page breaks (`w:br w:type="page"`) become forced page breaks.
- **Indents:** left, first-line, and hanging indents are converted to whole columns at the profile pitch (rounded to the nearest column). Right indents reduce the line width the same way.
- **Blank fields:** a line made only of blank fields is left out, whether it is its own paragraph or one Shift+Enter line of an address block (the usual Word layout).
- **Ignored with a warning:** fonts, sizes, colors, and italic (maybe shown as underline, configurable).
- **Errors:** tables, images, text boxes, multiple columns. These can't be typed sensibly.

## 6. Validation (`pipeline.py`, `merge.py`, `records.py`)
Each problem becomes an `Issue(level=error|warning, location, message)`, shown in a list in the GUI and printed by the CLI.
- **Field ↔ header:** every template field must exist as an Excel header. Matching is case- and whitespace-insensitive, and near misses get a "did you mean" suggestion. Unused columns are info only.
- **Excel:**
  - Missing or duplicate headers.
  - Empty rows (skipped).
  - Records where a field used in the template is blank (warning, listed per record).
  - Formula cells with no cached value, which happens when a file was generated rather than saved in Excel (error).
  - Numbers that look like lost leading zeros, e.g. a ZIP stored as a number without Excel's Zip Code format (warning).
  - A date-format picture applied to a field whose cell isn't a date (warning per record).
- **Value formatting** (`records.py` keeps raw values plus each cell's number format; `merge.py` formats them):
  - **Order of precedence:** the template's format picture (`{{OrderDate:MMMM d}}`, `\@`, `\#`), then the cell's Excel number format (`excelfmt.py`: currency, grouping, percent, zero-padded ZIPs, phone patterns, Accounting, conditions, dates and times), then defaults. Defaults: dates `MMMM d, yyyy`; whole numbers without `.0`.
  - **Rendering:** both renderers are our own code with English names, so results don't depend on the OS locale. Excel's built-in short date (format 14) is shown as `m/d/yyyy`.
  - **Unsupported formats** (fractions such as `# ?/?`) fall back to the defaults.
  - **Today's date:** `{{Today}}` (and a Word `DATE` field) give the print date in the same format, so a letter's date line can be generated.
  - **Numbers** with Excel's General format: whole numbers print without `.0`, others as stored. Text cells pass through unchanged.
- **Characters:** every character after the merge must be typeable with the profile's wheel. Known substitutions are applied automatically: smart quotes → straight, — → `--`, … → `...`, NBSP → space. Anything left over is reported per record with the field and the character.
- **Layout:**
  - A word longer than the line width (error).
  - Letters that run past one page (info, with the page count).
  - A heading or signature that would be split across pages (warning).
- **Template structure:** unsupported fields, unbalanced body markers, tables/images (errors).
- **Body zone:** info showing which paragraphs are body and how they were found (markers or auto-detection). A warning if typing errors are on but no body was found.

## 7. Simulated typing errors (`errors.py`)
- Errors are only applied to **body-region text that is not merge-field output**, so a recipient's name is never misspelled. They never apply to headers, footers, the date, the address, or the signature, nor to the first or last word of a paragraph, nor to words shorter than 3 letters.
- Error types, weighted 40/25/20/15 %:
  - adjacent-key substitution (QWERTY neighbor map; never at an `x`, whose correction would look like an x-out)
  - transposition
  - doubled letter
  - skipped letter
- Corrections use the **column overprint** the typewriter does naturally. The style is a setting: `xout`, `overstrike`, or **`mix` (default: substitutions are overstruck or x-ed out at random, the rest x-ed out)**.
  - **x-out**: the word is typed with the mistake up to a letter or two past it (or its end), each of those characters is struck over with `x`, and the word follows, typed correctly after a space. This uses extra columns.
  - **overstrike in place**: the right letter is struck over the wrong one, same width. Only for substitutions; the other kinds fall back to x-out.
  - In the model, `Span.over` / `Cell.over` hold the characters struck over each character. The renderer types them in left-to-right passes like underscores; the emulator, the GUI preview and the PDF show both characters on top of each other; text previews show the character on top.
- **Ordering:** errors are injected after the merge and **before** layout, so wrapping accounts for the extra columns.
- **Rate:** about N errors per 100 words of body text (default 1), with at least 12 words between errors.
- **Reproducible:** each letter's seed comes from the template name, the spreadsheet row and its values, plus salts saved in the session file: one for all letters and one per letter. "New errors" (the selected letter) and Letters > New Typing Errors for All Letters change them, so a reprint shows the same errors as the preview unless re-rolled. The CLI (`--typing-errors [RATE]`, `--error-style`) reads the same salts.
- Each letter lists its errors as an info issue ("typing errors: teh (xout), ..."); a warning says when errors are on but the body wasn't found.

## 8. Layout (`layout.py`)
- Profile values:
  - pitch (cpi)
  - left and right margin columns. On the Olympia/Swintec these are set on the keyboard and can't be set by escape code (the firmware's ESC sequences are only pitch, line spacing and half-line moves), and every power-on resets them to 10/75, so the profile records the power-on values. Lines never reach past the right margin, to avoid the firmware's mid-word auto-wrap (`0987`, not affected by margin release).
  - lines per inch
- **Paper and margins** (`frame.py`): the paper size and the four margins come from the template's first section in Word (`PageSetup`); `--paper-size`, `--top` and `--bottom` override them in the CLI. With the sheet against the paper guide, column c is c / pitch inches from its left edge. The guide goes at 10 on the paper scale on a Swintec and 0 on an Olympia (§16.1, 2026-11-22), the profile's `paper_guide`; it's broken on some machines, so the prompts also give the mark ("or at 10 on the scale"). Fitted to the typewriter as a `Frame`:
  - a wider left margin than the typewriter's starts each line with spaces (`indent`); a narrower one starts each line, and each overprint pass, with backspaces past the typewriter's margin (a negative `indent`, `Line.outdent`; `render._from_margin` uses up a pass's leading spaces first) when the profile has `left_of_margin = true` (all four built-in profiles, 0.1.7). Otherwise, by more than half a column, it asks for the sheet to go that much right of the paper guide (`shift_in`), in a warning and in each paper prompt. Backspacing rounds Word's margin to the nearest column (¾ in types at 0.8 in);
  - the right end of the lines is Word's right margin, but never past the typewriter's right margin (7.5 in from a sheet against the guide); a narrower margin in Word is a warning;
  - on single sheets the top margin is at least `load_offset_lines` (⅔ in on the Swintec), with a warning;
  - fewer than 20 characters per line or 6 lines per page is an error.
  The window shows the result on its Paper line, the preview draws the sheet at its size, and the emulator, PDF and paper prompts use it. Templates without a page setup get letter paper inside the keyboard margins. Word's default 1 in margins on letter give 65 characters per line (66 before 0.1.4, when the keyboard margins set the width).
  - **Left of the left margin (works on the Olympia, 2026-11-22; a Swintec not yet tried):** BS moves the column pointer left of the left margin, down to column 0 (`CD3`/`CED`, the same in 335-U), and typing a line moves the carrier to its first character wherever it is, so CR + BS × n starts a line n columns left of the margin without touching the keyboard. `testpage left` confirmed it on the Olympia (§16.1), and `frame.py` uses it instead of moving the sheet (0.1.7). The Swintecs are assumed to behave the same (the same code in 335-U; decided 2026-11-22 without a Swintec test). Never left of the sheet's edge (column 0 with the sheet at the guide), which a Word margin can't ask for.
  - **Wider paper (later):** text past 7.5 in needs the right margin moved on the keyboard after each power-on and a profile setting saying where; the typewriter can't report it, and a wrong setting gives mid-word wraps the emulator can't catch.
- Wrapping is greedy word-wrap per paragraph, working on Cells so bold, underline, and corrections carry through. Hyphenation: none at first; existing hyphens are allowed as break points.
- Alignment:
  - left
  - center and right, by padding with spaces
  - justify, by spreading extra spaces between words, last line left-aligned. An option can treat justify as left.
- Pagination:
  - Blank lines are tracked as well as text lines.
  - Breaks follow "keep with next" and widow/orphan rules (at least 2 lines).
  - Paragraph indents come from the template, in columns.
- **Page numbers (optional, generated):** Word's page numbering can't match after re-wrapping, so daisywriter numbers pages itself.
  - Settings: off / pages 2+ (the usual letter convention, default when turned on) / all pages; position (top or bottom; left, center, or right); format (`- 2 -`, `Page 2`, or a continuation heading such as `{{Name}}  -  Page 2  -  {{Today}}`, which can use merge fields).
  - The lines a page number uses, plus a blank line, are reserved before pagination, so body text never collides with it.
  - Page numbers are never body text, so they never get typing errors.
- **Paper stock:** page geometry (width, length, margins) comes from a *stock* (`letter`, `a4`, later `envelope_10`, …) combined with the profile, not from constants, so envelopes can be added later without changing layout code.
- Output is `Page[Line[Cell]]`, which is all the preview and renderer need.

## 9. Rendering (`render.py`) and profiles
A profile TOML describes one machine, for example:
```toml
name = "Swintec 1146 CMP"
transport = "usb_printer"   # or "serial" (future: Brother EP-44)
# usb = { vid = 0x067B, pid = 0x2305 } only to pick one adapter: otherwise any known one
paper = "single_sheet"      # or "continuous"
pitch_cpi = 10            # plus pitch_escape = "\x1bP" if host-settable
lines_per_inch = 6
page_lines = 66
margins = { left = 10, right = 75 }   # as set on the keyboard
newline = "\n"            # LF also returns on this firmware
bold = "overstrike"       # or { on = "\x1bO", off = "\x1b&" } on Diablo-style machines
underline = "overprint"   # BS/CR + "_" ; or { on = "\x1bE", off = "\x1bR" }
strikethrough = "-"       # overtyped on struck-out text, in its own pass
line_pause_s = 0.0
[charset]                 # Unicode → bytes, including SO/SI petals
"°" = "\x0e.\x0f"
```
- **Overstrike bold / overprint underline / strikethrough / strikeover corrections:**
  - Render each line as several passes: base text, then `CR` and passes containing only the bold re-strikes, underscores, strikethrough hyphens, and correction characters. Each cell takes its marks in that order, one per pass. Spaces are free carrier moves.
  - On the Olympia/Swintec, CR returns without a feed and the line buffer is a column image that is flushed on CR, so passes don't overwrite each other in the buffer.
  - The alternative is char/BS/char, which flushes on every BS and is slow.
  - Check on hardware how much darker a re-strike looks with a carbon versus a fabric ribbon.
- The preview renders the same Cells as HTML or a monospaced grid, with bold and underline shown and corrections drawn as overstrikes. That keeps the preview faithful.

## 10. Printing (`job.py`, transports)
- Data is sent in line-sized chunks with a per-line timeout. There's a status check (select, PE, error) before each page.
- **Paper handling** is set by the profile's `paper = "single_sheet" | "continuous"`, and the GUI can override it per session.
  - `single_sheet`: the job **pauses before every page**. The GUI shows "Insert sheet for letter 4, page 1 → Continue"; the CLI waits for Enter.
  - `continuous`: FF between pages and letters, with no pause.
- **Print queue in the GUI:** "Print all from #N", "Print selected", "Reprint". Each letter's status is saved in the session file (not printed, printing, printed, failed), so a crash or paper jam can resume.
- Cancel: stop sending, then CAN to discard the machine's unprinted buffer.
- Transports:
  - **Windows** (`transports/usbprint.py`, ctypes, no dependencies): SetupAPI lists the interfaces of `GUID_DEVINTERFACE_USBPRINT`, and the device path's `vid_xxxx&pid_xxxx` picks the first known adapter that's present (`transports/base.ADAPTERS`, or the profile's `usb`). `CreateFileW` opens it overlapped; each line is an overlapped `WriteFile`, cancelled with `CancelIoEx` when the timeout passes; `IOCTL_USBPRINT_GET_LPT_STATUS` (0x220030) reads the same status byte as GET_PORT_STATUS. `IOCTL_USBPRINT_SOFT_RESET` (0x220040) is available (`soft_reset()`) but not used until we know what it does to the typewriter.
  - **macOS/Linux:** pyusb, lifted from `cmpprint.py`. The bulk OUT endpoint comes from the descriptors (0x01 on the Prolific, 0x02 on the Sabrent).
  - **Adapters** (`transports/base.ADAPTERS`): the cable doesn't depend on the typewriter, so profiles don't name it; daisywriter opens the first known adapter that's plugged in. Known: Prolific PL2305 (067b:2305) and Sabrent's (1a86:7584, "USB Print", QinHeng/WCH, USB 1.1, printer class 7/1/2, bulk OUT 0x02 and IN 0x82, 32-byte packets, an empty IEEE 1284 device ID). A profile's `usb = { vid, pid }` still picks one.
  - **Dry run:** writes the bytes to a file.
  - **Emulator** (`transports/emulator.py`, `--emulate out.pdf`): a model of the Nakajima firmware (line buffer, CR/LF/BS/SO/SI/CAN/ESC, auto-wrap at the right margin, sheet loading and ejecting) that types onto virtual sheets and draws them as a true-size PDF (`pdf.py`, no dependencies). It reports firmware wraps, typing off the sheet, sheets still in the rollers, text left in the buffer, and cases the firmware notes leave open (spaces just before BS/ESC/SO/SI). It shows what we *think* the machine does; ink and darkness still need paper.

## 11. GUI (PySide6)
- **Top:** Template and Data with Browse, the worksheet, the typewriter profile; the date for `{{Today}}`, page numbers, justify; Reload (F5). The files are watched, so saving them in Word or Excel reloads the letters.
- **Left:** a letter table (checkbox, #, the first two columns of the row, pages, issues, print status). A checkbox in the header checks every letter (or unchecks them all when all are checked) and shows checked / dash / empty for all / some / none; "Check not printed" checks just the letters still to print. Letters that aren't printed yet start checked, and checks survive a reload.
- **Right:** the selected letter's sheets, drawn from the emulated typewriter, with the body shaded and the margins marked.
- **Bottom:** the validation issues list (click one to see its letter); Check typewriter (status light); the target (typewriter, or emulator saving a PDF); Print checked letters; Stop (after the line being typed).
- **Quit button** at the bottom right ("Exit" on Windows), as well as the menus.
- **Menus:** File (Open Template ⌘/Ctrl+O, Open Data ⌘/Ctrl+Shift+O, Reload F5 or ⌘/Ctrl+R, Print Checked Letters ⌘/Ctrl+P, Stop Printing ⌘/Ctrl+., Quit) and Help (About). On macOS, Quit (⌘Q) and About move to the application menu; on Windows, Quit is File > Exit (Alt+F4). Quitting while printing asks first.
- **Printing:** runs on a background thread, one letter at a time. Each sheet gets a paper prompt (none on the emulator). Letters with errors can't be printed; already-printed letters ask before printing again.
- **Session** (`session.py`): each letter's status is saved in `<data>.daisywriter.json` next to the data file, keyed by the template name, the spreadsheet row and the row's values. Statuses are not printed, printing (shown as "interrupted" after a crash), printed (with the time, and "changed since" if the letter's content changed), and failed (with the reason). Stopping part way through a letter marks it failed; stopping at the paper prompt leaves it not printed.
- **Later:** choosing which column names each letter; the typing-errors toggle and rate (phase 5).

## 12. Phases
1. **Core, no hardware:** ✅ done (branch `phase1-core`). model, template, records, validate, merge, layout, preview, and the `validate`/`preview` CLI. Tests use fixture docx/xlsx files (including a split-run placeholder and a complex MERGEFIELD).
2. **Typewriter output:** ✅ profiles, render, job, pyusb transport (Mac), the emulated typewriter, and `print`/`testpage` in the CLI. Printing works from macOS on the Swintec; see §16 for results and §16.1 for the checks left for the next session with the typewriter.
3. **GUI:** ✅ PySide6 window (`gui/`), session persistence (`session.py`), the paper-prompt flow, printing on a background thread with Stop, and an emulator target that saves a PDF; see §11. The preview draws the emulated sheets, so it shows exactly what the bytes produce. Not yet tried with the typewriter (§16.1).
4. **Windows:** ✅ the usbprint transport, tested on Windows CI (SetupAPI with no adapter; writes, a timeout and a status error against a named pipe), and with the typewriter on 2026-11-18 (§16.1): status, letters, a two-page letter, off-line and cable faults.
5. **Typing errors:** ✅ `errors.py`, overstrike rendering, previews, CLI options (`--typing-errors`, `--error-style`) and the window's controls; see §7. Not yet seen on paper (§16.1).
6. **Packaging:** ✅ `packaging/daisywriter.spec` (PyInstaller) freezes two programs into one folder: `daisywriter.exe` (the window, no console) and `daisywriter-cli.exe`. `packaging/daisywriter.wxs` (WiX 5.0.2; v6+ needs the Open Source Maintenance Fee EULA) packs it into a per-machine MSI (Program Files\daisywriter, a Start menu shortcut, the folder on PATH, upgrades replace older versions). CI builds it on Windows, installs it silently, runs both programs, checks the shortcut and PATH, uninstalls, and uploads the MSI (about 41 MB) as an artifact. Installed and tried by hand on Windows (2026-11-11). The icon (a daisywheel on paper) is drawn by `packaging/make_icon.py` into `packaging/daisywriter.ico` and `gui/icons/`. Not yet: an installer UI beyond Windows' progress bar, and code signing (Windows warns about an unknown publisher; see §14).
7. **Mac app:** ✅ The same spec builds `daisywriter.app` on macOS (both programs in `Contents/MacOS`, the `.icns` from `make_icon.py`, libusb from the `libusb-package` wheel so Homebrew isn't needed), and `packaging/make_dmg.sh` packs it in a drag-to-Applications disk image (about 45 MB, Apple silicon only). ## 13. Testing
**Principle:** the typewriter connection (`Transport`) is the only part that needs the machine. Everything above it is tested without hardware, using a fake transport from phase 2 on, so hardware tests stay few and manual.

### Layers
| Layer | What | Where |
|---|---|---|
| Unit | Each module: values, template, region, records, layout, profile | `tests/test_*.py` |
| Real-Word fixtures | Templates saved by Word (spell-check marks, Shift+Enter address blocks, docDefaults spacing). Add Google Docs / LibreOffice exports when available. | `tests/fixtures/`, `test_word_fixture.py` |
| Golden previews | Plain-text preview of every fixture letter, checked in; layout changes show as diffs. Regenerate with `uv run pytest tests/test_golden.py --update-golden` and review the diff. | `tests/golden/`, `test_golden.py` |
| Properties (Hypothesis) | Wrapping never exceeds the margins, loses or reorders text, or drops formatting; justified lines are full width. Pagination never overfills a page, keeps order, starts no page with a blank line, and leaves ≥2 lines on each side of a split. | `test_properties.py` |
| End-to-end | Template + data → letters through `pipeline.run` and the CLI | `test_pipeline.py`, `test_cli.py` |
| Emulated typewriter | Every golden letter rendered to bytes, sent through the print job to the firmware model, and compared strike by strike with the layout (characters, re-strikes, underscores, hyphens); no firmware wrap; every sheet fed past the rollers. | `test_emulator.py` |
| Hardware | `@pytest.mark.hardware`, skipped unless `--hardware` | from phase 2 |

### Added by later phases
- **Phase 2 (output):**
  - Golden byte streams per profile: bold re-strikes, underline passes, charset/SO-SI mapping, newlines.
  - A `FakeTransport` that records bytes and simulates off-line, paper empty, write timeouts and adapter stalls, for testing the send loop, cancel (CAN) and paper prompts.
  - The pyusb backend against a mocked `usb.core` device.
- **Phase 3 (GUI):** done in `test_gui.py` and `test_session.py`; Qt runs offscreen (`QT_QPA_PLATFORM=offscreen`, set in `conftest.py`). `pytest-qt` flows against the fake transport:
  - load files
  - review issues
  - select letters
  - print, reprint, and resume after a failure
- **Phase 4 (Windows):** the usbprint backend's pure parts (device path matching, status bits) on Windows CI. Real I/O only through hardware tests.
- **Phase 5 (typing errors):**
  - the same seed gives the same letter
  - the error rate stays within bounds
  - no errors in field text or outside the body
  - the preview matches the bytes sent
- **Phase 6 (installer):** done in the `installer` CI job: build the MSI, install it silently (`msiexec /qn`), run `daisywriter-cli` (profiles, make-samples, an emulated print with typing errors), open and close the window (`DAISYWRITER_SMOKE_TEST`), check the Start menu shortcut and PATH, uninstall and check that everything is gone. WiX warnings are errors (`-wx`): a missing folder is only a warning and gives an empty MSI.

### Hardware checklist (`--hardware`, plus a printed test sheet)
1. Status read; soft reset.
2. One-line print.
3. A margin-edge line that must not trigger the firmware's auto-wrap.
4. Off-line during a job: a clean timeout, then resume.
5. Paper-empty stall, then recovery on the next run.
6. Judged by eye on the test sheet: re-strike darkness (fabric vs carbon ribbon), underline alignment, strikeover appearance.

### CI
`.github/workflows/ci.yml` runs ruff, pytest and a CLI smoke test on Ubuntu, macOS and Windows. The MSI job is added in phase 6.

### Bold on carbon film
Carbon film is fully black after the first strike, so re-striking in the same spot adds little. Bold needs wider strokes, which Diablo/Qume printers got by striking again 1/120 in to the side. Options considered for the Nakajima machines:
- **Re-strike from the right** (`testpage bold`, `render.reverse_pass`): type the bold text right to left with BS so the carrier reaches each letter from the right. Play in the carrier drive makes each letter land a little to the side. **Works on the Swintec** (2026-11-10, and the 1146 CM 2026-11-18) **and the Olympia** (2026-11-22): clearly bolder, still clean. Profiles choose the direction of each re-strike with `bold_restrikes`.
- **Sub-column offsets by switching pitch:** ruled out. The carrier moves in 1/60-in steps (6/5/4 per character at 10/12/15 cpi), and a pitch change rounds the carrier column (`0DA6`), but `06C4` then moves the carrier by the remainder, so it always lands back on the new grid.
- **Platen offset (ESC D / ESC U backlash):** about 1/50 in, varies between units, and doesn’t return reliably to the line (see `FIRMWARE_NOTES.md` in the Olympia repo). Ruled out.
- **Harder strikes:** hammer force is a ROM table plus the impression switch, which only changes by hand and affects every character. Ruled out.
- **Fallback** (not needed on the Swintec): show bold as underline (a typist's convention), as a profile setting. A ROM patch adding Diablo-style `ESC O` / `ESC &` also looks feasible (free space at `DF3–EFF`, a hook at the end of the ESC chain and in the strike sequence at `A57`) but is only 1/60-in resolution.
